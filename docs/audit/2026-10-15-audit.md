# Code audit and repair sweep — 2026-10-15

**Auditor**: Claude Code (lead review + three independent audit lenses)
**Target**: darshini v1.4.0 → repaired as **v1.4.1**
**Scope**: all 11 files under `src/` (3,629 lines at entry), `tests/`,
`icons/`, `mime/`, every document under `docs/`, `README.md`,
`SECURITY.md`, `CONTRIBUTING.md`, and both workflows under `.github/`.
Toolchain held at cyrius 6.7.9 and darshana 1.3.0 by decision.

## Summary

| Area | Confirmed | Fixed in 1.4.1 | Deferred to the roadmap |
|---|---|---|---|
| Security | 2 | 2 | — |
| `--git` correctness | 7 | 7 | full `.gitignore` semantics (1.5.0) |
| Core listing correctness | 11 | 11 | — |

| Code hygiene | 7 | 7 | — |

Of these, three were **major**: a hostile mtime put raw control bytes on
the terminal and could spin for minutes (S-1); `-l --git <file>` was wrong
for every file (G-1); a `..` in the path broke every `--git` lookup (G-2).

**Method.** Three agents audited independently — (1) correctness and
robustness of the listing pipeline, (2) security and robustness of the
untrusted-input parsers, (3) docs, CI and test coverage against the code —
while the lead reviewed every module. Every finding below was reproduced
against the v1.4.0 binary before any code changed; reasoned-only
suspicions are listed separately. Each repair was then A/B-verified (see
*Verification*).

**Verdict.** v1.4.0 had one more terminal-injection path (metadata, not
names), a parser that silently accepted only one of three index formats
and then lied about it, and a `--git` column that was wrong for three
common invocation shapes. None was memory-unsafe: 1,500 mutated
`.git/index` files and random `.gitignore` bodies through `--git -T -l`
produced no crash and no timeout, and every stack buffer is within its
consumer's maximum write.

## Steps 3 + 5 — Internal review and security audit

### Security

**S-1 (major) — a file's mtime reached the terminal raw, and could hang
the run** (`render.cyr` `format_mtime`). No upper bound on the epoch.
`_chrono_w4` writes `48 + year / 1000` through `store8`, so a five- or
six-digit year emits whatever byte that truncates to: year 10000 →
`:000-01-01`; years 235,7xx / 235,8xx → `ESC 7` / `ESC 8` (save / restore
cursor), so a later row overwrites an earlier one — the hide-a-sibling
effect v1.3.2 closed for names; other ranges → raw `0x9B` (CSI) and CR.
The v1.4.0 sanitizer covers names only. `epoch_to_date` also loops once
per year: 1e16 took 1.1 s per entry, 9e18 timed out at 20 s (≈19 min
extrapolated). Reachable: `tar --format=posix --mtime=@7378962105600`
extracts onto tmpfs with the timestamp intact. **Fixed**: past
9999-12-31 23:59:59 UTC → the existing `????-??-?? ??:??` placeholder.
Unit tests at both sides of the boundary; fuzz target 6
(mutation-validated); a CI gate on tmpfs.

**S-2 (minor) — opens could block forever** (`mime.cyr`, `git.cyr`,
`walk.cyr`). Every open follows a stat, and the file can be swapped
between them; plain `O_RDONLY` follows symlinks and blocks on a FIFO with
no writer. A racing rename hung `--mime` 3 times in 88 runs. As root,
`/proc/kmsg` (a size-0 regular file) would block the read. **Fixed**: on
Linux every open is `O_NONBLOCK | O_CLOEXEC` (the mime probe also
`O_NOFOLLOW`), `fstat` must confirm a regular file, and a file under 2
bytes is not read.

### `--git` correctness

All checked against `git ls-files` / `git status` on real repositories.

- **G-1 (major)** — `-l --git <file>` and `-ld --git <dir>` always `?`:
  the argument was looked up as `<path>/<path>`. Also re-parsed the index
  per argument (18 args × 90k entries: 1.1 s, 430 MB). **Fixed**: status
  of the listing path itself; one parse per repository per run.
- **G-2 (major)** — a `..` the root walk had to cross stayed in the
  repo-relative prefix (`src/sub/..`), so every lookup missed; a symlink
  into another repo bound to the wrong index. The 2026-08-23 audit kept
  `..` lexical to protect the `/A/link/..` case and checked only that.
  **Fixed**: the physical path from the kernel (`/proc/self/fd/N` of the
  opened directory), which resolves both and keeps `/A/link/..` correct.
- **G-3 (minor)** — index v3 (`git add -N`, sparse checkout), v4
  (`feature.manyFiles`) and SHA-256 repos: the parse failed, the failure
  was ignored, the column showed every file `?`. **Fixed**: v2–v4, SHA-1
  and SHA-256; an unusable index declines the column.
- **G-4 (minor)** — the 0xFFF long-name branch started counting at 0xFFF,
  so a 4095+ byte path ended parsing (reproduced with `git update-index
  --cacheinfo`). **Fixed**, plus non-empty / NUL-terminated name checks.
- **G-5 (minor)** — size and mtime compared at 64 bits against git's u32
  fields: every file ≥ 4 GiB and every pre-1970 mtime showed `M`.
  **Fixed**.
- **G-6 (minor)** — a `.git` file (submodule, worktree) was stepped past
  to the enclosing repository. **Fixed** by declining; following
  `gitdir:` is roadmap 1.5.0.
- **G-7 (minor)** — a repo rooted at `/` was never found from below (the
  walk stopped before probing `/.git`). **Fixed**.
- **G-8 (perf)** — directory status scanned the whole index per directory
  entry (90k entries / 5k dirs: 10.9 s vs 0.87 s without `--git`).
  **Fixed**: a prefix set, built once from the sorted index.

### Core listing correctness

- **C-1** — `-F` ignored path arguments; `-dF` gave `/` for a symlink to a
  directory where `ls -dF` gives `@`. **Fixed** (indicator from an lstat).
- **C-2** — `-F` left a trailing pad space on a pipe and in `-1` / `-l` /
  `-T` (`while IFS= read -r` read `"plain "`). **Fixed**: the pad is now
  grid-only. Changes pipe bytes under `-F` for names without an
  indicator — classed as a fix: trailing whitespace a script consumer
  must strip is the surprise CLAUDE.md calls a bug, and `ls -F` never
  emits it.
- **C-3** — `--` was an unknown flag: no safe way to pass a glob holding a
  `-`-leading name. **Added**.
- **C-4** — an unreadable directory under `-T` looked empty (exit 0); a
  getdents error part-way silently truncated a listing (reproduced with a
  seccomp launcher forcing EIO). **Fixed**: `dir_list_checked`, a stderr
  diagnostic after the directory's line, exit 1.
- **C-5** — `--help` / `--version` exited 0 on a write failure. **Fixed**.
- **C-6** — `-l --mime <file>` dropped the column. **Fixed**.
- **C-7** — case-only collisions sorted in getdents order. **Fixed**: raw
  tiebreak.
- **C-8** — `-h` overflowed above ~9.2e17 (`838860.)T`); no P / E.
  **Fixed**.
- **C-9** — `--level` had no overflow check despite its comment.
  **Fixed** (bound 2^31 − 1).
- **C-10** — icon / mime / ignore rules saw the whole path argument, not
  its name (`-l docs/README.md` lost the README glyph). **Fixed**.
- **C-11** — `xlsx` was in `mime/default.cyml` but not the compiled table
  (the only drift found; icons are byte-identical, 82 / 82). **Fixed**.

### Performance

- **P-1** — every `d_write` was a `write(2)`: 8 per `-l` row, one per
  padding space and per tree ancestor. **Fixed**: 64 KB stdout buffer,
  line-buffered on a terminal, flushed before any stderr write and before
  the exit check.
- **P-2** — `-T` allocated its stat and formatter scratch per entry, never
  reclaimed. **Fixed**: stack buffers.
- **P-3** — G-8 above.

### Code hygiene

Lint warnings (2); dead code (`emit_colored`, `emit_icon`, `d_open_ro`);
three copies of the git status lookup; a duplicate agnos `getdents`
enumerator the stdlib now provides; a hand-bumped version literal
(`CYRIUS_PKG_VERSION` works under 6.7.9 on every target — probed); a
test-suite copy of `_parse_pos_int` (now `src/cli.cyr`); stale comments
(compute_decor's "24-byte struct", the nonexistent `compute_colors`,
`_path_join_into`'s "caller sizes the buffer", "matches `ls -h`", the
sort bench figure, the magic-byte order claim, long.cyr's "`-> target`
lands at M6/M7", git.cyr's "linear scan, hashmap post-v1"). All fixed.

One assumption corrected along the way: comments claimed a function must
be defined above its first use, across includes. cycc 6.7.9 resolves
later definitions in the same file and in later includes (probed); the
include order is convention.

## Step 4 — External research (reference behavior)

The comparisons that decided each fix: GNU `ls` (`-F` never pads; `-dF`
on a symlink gives `@`; `-R` reports an unreadable directory and exits
non-zero; `--` ends options), git (physical cwd for repo discovery; u32
`sd_size` / `sd_mtime`; v3 / v4 / SHA-256 index layouts; `.git` files for
submodules and worktrees), and `tree` (an unreadable directory is
reported inline). Deliberately **not** ported, per the out-of-scope list:
gitignore-aware *filtering*, alternate sorts, `-R`, environment theming.

## Verification

A 76-mode harness, each mode on a pipe and under a real PTY (`TIOCSWINSZ`
set before fork, then `setsid` + `TIOCSCTTY`) at 100, 53 and 0 columns —
304 captures — on a fixture holding every file type, special mode bits,
magic-byte files, a sparse 5 GB file, a 1960 mtime, a CRLF `.gitignore`,
all git states, unreadable / unsearchable directories, UTF-8 / Latin-1 /
truncated names, nine control-byte names and dash-leading names.

- **v1.4.0 → v1.4.1**: 113 / 304 differ. Each was classified by script
  (trailing-pad-only) or line by line: `-F` pad, `-F` on arguments, the
  u32 compare, tree read errors, `-l --git <file>`, mime on a file
  argument, `--`, help / usage text, `--level` overflow. No other line
  changed. Under a PTY the tree's error lands immediately after the
  unreadable directory's line — the buffer preserves stdout / stderr
  order.
- **aarch64 vs x86_64** (`qemu-aarch64`): 0 / 304 differ.
- **DCE vs normal build**: 0 / 304 differ.
- **agnos** (`mirshi --root`): 21 modes, 6 differ, all intended. Suite
  398 / 400 (the pre-existing `-ENOENT` pair), fuzz ok.
- **Fuzz mutation check**: removing the mtime bound fails target 6 at
  once.

## Suspected, not proven

- `epoch_to_date` returns 0 when its allocation fails, and `format_mtime`
  would dereference it; more generally no caller checks `alloc()` for 0,
  so exhausting memory on an enormous `-T` would crash rather than report.
- Bidi overrides (U+202E) pass the sanitizer, so a name can be
  display-spoofed. darshana ADR 0004 records this as deliberate.
