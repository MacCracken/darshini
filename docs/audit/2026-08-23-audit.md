## Step 3 — Internal review + Step 5 — Security audit

### MAJOR-1 — `_path_join_into` wrote past its buffer (`color.cyr`)

Found independently by **four** lenses (correctness, security, tests,
robustness).

`_path_join_into` `memcpy`'d `dir + '/' + name + NUL` into a caller-supplied
buffer with **no capacity check of any kind**, while its only caller hands it a
fixed `alloc(PATH_BUF_SIZE)` = 4096. A listing path near `PATH_MAX` holding a
`NAME_MAX` entry needs 4096 + 1 + 255 + 1 = 4353 bytes.

Measured: a 3915-byte directory holding a 255-byte filename wrote **76 bytes
past the end of the allocation**, reachable purely from `argv`. It does not
crash — the bump allocator's slack absorbs it — which is why it survived from
v1.1.2 through v1.3.1.

The function's own header comment claimed the caller was responsible for
sizing; the caller could not be, because the buffer is fixed and the inputs
are not.

**Fixed**: bound computed before the first write; an overlong join yields an
empty cstr and returns 0. The caller's `lstat` then fails and the entry renders
with `?` placeholders — the *same row* the unbounded code produced, because a
path that long fails the syscall with `ENAMETOOLONG` anyway. Verified
output-identical to the v1.3.1 binary on the overflow case.

### MAJOR-2 — terminal escape injection via filenames (`color.cyr`)

A filename is attacker-controlled input: an extracted tarball, a cloned repo, a
shared downloads directory. Through v1.3.1, entry names were written to the
terminal byte-for-byte.

Demonstrated against the v1.3.1 binary under a real pseudo-terminal:

| Filename | Effect |
|---|---|
| `clr` ESC `[2J` `gone` | clears the screen |
| `title` ESC `]0;PWNED` BEL `end` | sets the terminal window title |
| `cr` CR `OVERWRITE` | overwrites the rendered line |
| `b` ESC `[1A` ESC `[2K` `harmless.txt` | erases the **preceding** entry — a hostile archive can hide a sibling file from the listing |
| `evil` ESC `[31m` … ESC `[0m` | resets the SGR state darshini itself set, corrupting every later entry's color and misaligning the columns |

`ls`, `eza` and BSD `ls` all sanitize on a TTY; darshini did not.
`SECURITY.md` claimed it did (see MAJOR-7).

**Fixed**, with the maintainer's explicit sign-off on the bump level and the
substitution style. On a TTY, `?` replaces each C0 byte (0x00–0x1f), DEL, and
the UTF-8 encoding of the C1 controls (0xC2 0x80–0x9F) — the shape `ls -q`
uses. One `?` **per byte**, which matters: every width calculation in the
codebase measures `str_len(name)`, so a length-preserving substitution keeps
all of that arithmetic correct with no changes anywhere else, and incidentally
*fixes* the alignment of such rows.

Bytes ≥ 0x80 are untouched, so UTF-8 names render intact. That relies on
`load8` being **unsigned** — established by probe on cycc 6.5.35 before writing
the predicate, and now guarded by seven high-byte assertions that all fail if it
ever changes.

TTY-only, keyed on `term_width() > 0` and deliberately **not** on `want_color`:
`--no-color` disables decoration, not the terminal. On a pipe the true bytes are
written, matching `ls --quoting-style=literal`, so `darshini | while read -r f`
still yields an openable name — verified round-trip on all 9 hostile fixtures.

### MAJOR-3 — `--git` reported every tracked file as untracked (`git.cyr`)

`darshini --git` with no path, inside any repository subdirectory — the single
most common form of the flag — reported **every tracked, clean file as `?`
(untracked)**.

`main.cyr` supplies `"."` when argv has no positional. `_git_make_absolute`
concatenated cwd + `/` + `.` verbatim, so `_git_find_root`'s probe of
`/repo/src/./.git` failed and it truncated past it to `/repo`, leaving the
listing path with an un-normalized tail. `_git_entry_relpath` then built
`src/./a.txt`, which misses a `tracked_map` keyed on `src/a.txt`.

It worked at the repo root only by accident, and broke identically for
`--git .`, `--git ./`, `--git src/`, and any absolute path with a trailing
slash.

**Fixed**: `_git_normalize_abs` collapses `//`, drops `.` components, and
strips trailing `/`. Verified across 11 invocation forms, all now agreeing with
`git ls-files`.

⚠ `..` is deliberately **not** resolved lexically. The refuting agent
demonstrated that doing so regresses a case that is correct today: with
`/A/link` → `/B/sub`, `darshini --git /A/link/..` currently resolves through
the kernel's symlink-aware `stat` probe and correctly binds to repo B. Lexical
resolution would rewrite it to `/A` and bind to the wrong index. Verified
unchanged after the fix.

### MAJOR-4 — `-T --git` mislabelled everything below depth 1 (`tree.cyr`)

`GitCtx`'s listing prefix is captured once at the **tree root**, but the
recursion passed each entry's bare basename. A tracked `src/deep/c.txt` was
looked up as `c.txt`, missed, and rendered `?`. Every tracked file below depth 1
was wrong.

**Fixed**: a `rel_prefix` is threaded through `_tree_recurse` / `_tree_decor`
and joined onto the basename for the index lookup, via a new
`git_status_for_sub`. Ignore-pattern matching still uses the basename, so
v1.3.1 semantics there are unchanged. `git_status_for` remains as an
exact-behavior wrapper. Depth 1 is byte-identical (empty prefix); only depth ≥ 2
changes.

All four call sites were updated together — Cyrius leaves missing arguments as
register garbage, though `cycc` 6.5.35 does in fact reject an arity mismatch at
compile time, which is a stronger guarantee than CLAUDE.md's warning implies.

### MAJOR-5 — `-T -l` printed fabricated metadata (`tree.cyr`)

`_tree_emit_long_prefix` was called **before** the caller's `rc >= 0` guard, so
a failed `lstat` left it reading a never-written `alloc(144)` and rendering a
confident `---------- 0 1970-01-01 00:00`.

Reproduced on a readable-but-not-searchable directory (mode 0600: `getdents`
succeeds, `lstat` on the children returns `EACCES`), where flat `-l` correctly
showed `?????????? ? ????-??-?? ??:??` for the same entries. `-T -l` was
inventing data.

**Fixed**: the placeholder branch now matches flat `-l`, and takes its mtime
placeholder from `format_mtime`'s own negative-epoch path rather than a second
copy of the byte pattern, so the two cannot drift.

### MAJOR-6 — `format_mtime` emitted non-ASCII bytes for pre-1970 mtimes (`render.cyr`)

Pre-1970 epochs drive `epoch_to_date` into negative components; `_chrono_w2`
then writes `48 + n` for a negative `n`, emitting bytes below `'0'`. A 1960
mtime rendered as `1970-01-\xD4+ /.:00` — **0xD4 straight into the terminal**,
in a field contracted below its fixed 16 bytes, misaligning every following
column.

Reachable from restored backups, extracted tarballs preserving timestamps, and
`touch -d`.

**Fixed**: `epoch < 0` degrades to the `????-??-?? ??:??` placeholder at exact
width. Epochs ≥ 0 byte-identical; the epoch-0 boundary is asserted.

### MAJOR-7 — `SECURITY.md` documented a control that did not exist

`SECURITY.md` stated darshini "sanitizes entry names before rendering
(substitutes a placeholder for control characters)". It did not — see MAJOR-2.
It also promised to "refuse to parse `.git/` files larger than reasonable
limits", where the actual behavior was silent truncation — see MINOR-2.

A security policy that overstates its controls is worse than one that admits a
gap, because it stops a reader from applying their own mitigation.

**Fixed**: both bullets rewritten to state exactly what v1.3.2 does, including
the deliberate TTY/pipe asymmetry, with the prior state called out explicitly.

### MINOR-1 — CRLF `.gitignore` matched nothing (`git.cyr`)

On a `.gitignore` authored with CRLF endings — any Windows or cross-platform
contributor — **no ignore rule fired at all**. The trailing CR was trimmed, then
silently re-admitted: the restore used `line_end`, which still points at the
`\n`. `build/\r` is not a directory pattern (last byte isn't `/`) and `*.swp\r`
matches nothing.

Verified against `git status --ignored`, which correctly reported the same files
as ignored. **Fixed**; LF inputs byte-identical. A dead first line-scan (7 lines,
never read) was removed in the same pass.

### MINOR-2 — oversized `.git/index` silently truncated (`git.cyr`)

`_git_slurp` allocated a fixed 4 MB and did **one** `sys_read`. Two defects: a
single read is not guaranteed to fill the buffer, and an index larger than the
cap was silently truncated, with every entry past the cutoff reported
untracked.

**Fixed**: size from `stat(2)`, read to EOF, and treat the cap as a sanity
ceiling (raised to 256 MB) rather than a truncation point. A file beyond it
yields no git context — the column silently doesn't appear, the same shape as
the out-of-repo case — instead of appearing and lying.

Side benefit: a FIFO stats with `st_size` 0 and is now refused, so `--git` no
longer blocks forever on a planted `.git/index` FIFO. Real `git` **does** hang
on that (verified with git 2.55.0), so this is a small improvement over the
reference rather than a parity fix.

### MINOR-3 — dangling symlink as an argument aborted the run (`walk.cyr`)

`classify_path` uses the follow-stat, so a broken symlink named on the command
line classified as `-ENOENT`: `darshini broken` printed
"no such file or directory" and exited 1. The same symlink listed as a *member*
of its parent directory rendered fine as `lrwxrwxrwx … broken`, and `ls -l
broken` shows the link and exits 0. In a multi-path invocation one dangling
link forced a non-zero exit for every other path.

**Fixed**: on stat failure, retry with `lstat`; if the link itself exists, treat
it as a non-directory. Only paths that previously *errored* change behavior —
verified that symlink-to-directory arguments still follow to their target, and
that a genuinely missing path still exits 1.

## Deferred — accepted, not fixed in 1.3.2

| Item | Rationale |
|---|---|
| **`sys_write` return values are never checked** (56 sites) | Real: a full filesystem yields exit 0 with truncated output. The fix is a looping `d_write` wrapper plus a sticky failure flag threaded to `main()` — a change touching every output path, which does not belong in a patch cut alongside seven other repairs. Tracked for 1.4.0. |
| **`-l` double-`lstat`** | `compute_decor` and `render_long` each stat every entry: 2 syscalls per entry where 1 suffices. Pure performance, no wrong output. Needs `compute_decor` to widen its returned struct and hand stat buffers back. Tracked. |
| **`tests/darshini.fcyr` is a stub** | `cyrius fuzz` passes while executing zero darshini code. A 512-line replacement harness was drafted by the tests lens; adopting it wants its own review pass rather than being folded into a security cut. Tracked. |
| **agnos `_d_dir_list_agnos` still bump-allocates** its 4 KB scratch | Recorded in [003](../architecture/003-allocation-lifetime-model.md) and state.md. Agnos behavior change; wants its own test pass under `mirshi`. |
| **`format_mtime` reads chrono's `DateTime` by raw byte offset** | cycc 6.4.67 added accessors specifically to make that layout private. Safe today (the layout is unchanged); migrating is a 1.4.0 item. |
| **`-T --git <dir>` root line** shows `?` for the tree root itself | Pre-existing and unchanged by MAJOR-4; the root's rel should be the listing prefix itself rather than prefix + name. Cosmetic, one line, out of scope for this cut. |
| **aarch64 build renders `?` for stat-derived columns** | Known and documented. Not a supported target; see [002](../architecture/002-agnos-fs-abi-split.md). |

## Verification

Every fix was verified against a **v1.3.1 reference binary** built from the
prior tree with cycc 6.4.24.

- **31 A/B comparisons** on well-formed input — 17 under a real 80×24
  pseudo-terminal, 14 on a pipe, across the fixture tree and darshini's own
  repository, covering every flag and combination. **Zero differences.**
- **11 `--git` invocation forms** cross-checked against `git ls-files`.
- **CRLF vs LF `.gitignore`** cross-checked against `git status --ignored`.
- **9 hostile filenames** under a pty: zero residual control bytes after
  stripping darshini's own SGR, all names still openable from the pipe output.
- **UTF-8 integrity**: CJK, accented, emoji, Greek, and high-byte names render
  intact on a TTY.
- Both cross-targets rebuilt clean; the agnos binary re-run under `mirshi`.
- All 14 CI smoke gates, the security scan, the docs gate, and the
  version-consistency gate replayed locally.

`cyrius test`: **233 → 272** assertions, 0 failed. The 39 new ones cover the
sanitizer predicate (including the `load8`-signedness guard), path
normalization, CRLF ignore parsing, and negative-epoch mtimes.
